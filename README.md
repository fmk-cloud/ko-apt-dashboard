# k.apt_v26 · 영등포·성동·마포

v25의 화면 배치·급지표·지도 업로드·저장/되돌리기/복구·가격 계산을 유지하고 성동구와 마포구 공식 매매·전세·용적률 데이터를 추가했습니다. ZIP을 풀고 `index.html`을 열면 포함된 데이터를 바로 볼 수 있습니다.

## 포함 데이터

기간: 2024.01~2026.09. 세대수 300 이상 아파트·주상복합, 임대 전용 제외.

| 지역 | 대상 단지 | 매매 자료 | 순수 전세 자료 | 용적률 확인 |
|---|---:|---:|---:|---:|
| 영등포구 | 82 | 6,534건 | 11,099행 | 41 |
| 성동구 | 61 | 6,356건 | 11,679행 | 27 |
| 마포구 | 65 | 5,515건 | 11,765행 | 50 |
| 합계 | 208 | 18,405건 | 34,543행 | 118 |

영등포구 v25의 매매 데이터는 동일합니다. 지역 즐겨찾기에 성동구·마포구를 추가했습니다. `전체`를 누르면 세 구를 함께 비교합니다. 기존 저장 필터는 유지하고 신규 지역 칩만 처음 한 번 추가합니다.

지역·세대수·면적·준공일자·기준가·용적률·전세 갭·신뢰도 필터를 세 구에 동일하게 적용합니다. 용적률 미확인 값은 0으로 취급하지 않고 숫자 범위를 지정하면 제외합니다. 전세 갭은 선택한 시작월을 기준으로 계산합니다. 해당 시작월과 이전 5개월, 같은 실제 면적 ±0.1㎡, 4층 이상·최고층 제외 조건의 순수 전세 중 최고가를 사용합니다. 기본은 신규 계약입니다. 조건에 맞는 전세가 없으면 값을 만들어 넣지 않습니다. 숫자 클릭으로 선정 거래를 확인할 수 있습니다.

**성동구·마포구 지하철 도보 정보는 아직 검증하지 않았습니다.** 지역·APT 비교를 사용하세요. 역 필터는 검증된 기존 도보 정보가 있는 단지만 포함하므로 신규 두 구를 온전히 검색하지 못합니다. 직선거리를 도보 시간으로 바꾸어 채우지 않았습니다.

## 보류와 연결 기준

이름·법정동·지번·건축연도를 대조합니다. 연결표와 근거는 `config/seoul-bindings.json`, 제외/보류는 `config/catalog-exclusions.json`, 수집 결과는 `reports/update-report.json`에 기록했습니다.

- 기존 보류: 신대림자이(각 차수 300세대 미만), 여의도광장(관리 단위와 거래 단위 분리 확인 필요).
- 신규 보류: 공덕SK리더스뷰 1단지(대장의 472세대와 공식 목록의 306세대 불일치), 마포자이 더 센트리지(목록 준공연도 2018/거래 건축연도 2022 충돌), 금호1차푸르지오(목록 상세 지번 971/거래 지번 917 충돌), 마포그랑자이(전체 관리 1,248세대에 300세대 미만 2단지 포함; 1단지 세대수 분리 검증 필요).
- 당산상아는 공식 목록에는 있지만 해당 기간 거래 연결을 확인하지 못해 확인 필요로 표시합니다.

따라서 이 자료를 세 구의 모든 아파트가 빠짐없이 연결된 완전 목록으로 보지는 마세요. 원천 단지 등록 누락·주소 충돌·지연 신고가 있을 수 있습니다. 아래 출처의 공개자료를 검증해 연결한 범위입니다.

## 기존 저장소 적용

1. 기존 저장소를 백업한 뒤 ZIP의 파일을 같은 경로에 덮어씁니다. `index.html` 한 파일만 교체하면 화면 데이터는 바뀌지만 다음 갱신이 세 구에 적용되지 않습니다.
2. 특히 `config/`, `scripts/`, `data/`, `reports/`, `tests/`, `.github/workflows/update-data.yml`을 함께 반영합니다. `.github`는 압축 프로그램에서 숨김 폴더로 보일 수 있습니다.
3. 같은 저장소·사이트 주소를 유지하면 해당 브라우저의 필터 저장과 업로드 지도는 기존 저장 키로 계속 사용합니다. 다른 도메인·브라우저·로컬 파일 주소에서는 저장 내용이 자동 이동하지 않습니다.
4. 현재 데이터 확인에는 **Actions → Run workflow가 필요 없습니다.** 이미 수집한 자료를 포함했습니다. 새 수집 확인을 원할 때 수동 실행하면 됩니다.

## 월별 자동 갱신

GitHub Actions는 매월 1일 한국시간 04:00을 목표로 세 구를 수집합니다. UTC 19:00과 한국 달력 1일 여부를 함께 검사합니다. GitHub 예약 실행은 지연될 수 있으므로 정확한 시각 실행을 보장하지는 않습니다.

기존 저장소의 Actions가 활성화되고 workflow에 쓰기 권한이 있어야 하며, 갱신 커밋이 기존 배포에 연결되어 있어야 사이트에 자동 반영됩니다. ZIP 다운로드나 로컬 HTML 실행만으로 자동 갱신이 실행되지는 않습니다. 이 작업은 원격 저장소 업로드·배포까지 수행한 것은 아닙니다.

인증키 없이 서울시 공식 공개 내려받기를 사용합니다. 목록은 한 번, 매매와 현재 접수연도 전세는 각 구별로, 용적률과 전세 연도 ZIP은 실행 중 공유해 수집합니다. 매달 제공 범위를 다시 받아 취소·지연 신고를 반영하며 과거 전세 ZIP도 다시 내려받습니다. 현재 포함된 2024·2025년 전세 ZIP은 2026.10.05 내려받은 공개본이고, 현재 매매·전세·목록·용적률 응답은 이번 작업에서 새로 확보했습니다. 파일별 해시는 보고서에 있습니다.

구별 응답 코드, 목록 급감, 구별 월 전체 누락, 기존 단지 거래·전세 급감을 검사합니다. 신규 지역 전세·용적률 수집 실패 시 새 범위를 발행하지 않습니다. 이미 정상 수집된 전체 범위에서 전세·용적률 수집이 실패하면 기존 정상 기능 자료를 유지하고 상태와 사유를 표시합니다. 매매 수집 실패 시 기존 스냅샷을 유지합니다.

Python 3.11 이상, 표준 라이브러리만 사용합니다.

```bash
python -m unittest discover -s tests -v
python scripts/update_public.py
python scripts/validate.py
```

## 원천과 해석

- [서울시 공동주택 현황 OA-15818](https://data.seoul.go.kr/dataList/OA-15818/S/1/datasetView.do): 세대수·주소·준공연도.
- [서울시 부동산 실거래 OA-21275](https://data.seoul.go.kr/dataList/OA-21275/S/1/datasetView.do): 매매. 해제·권리 거래 제외.
- [서울시 전월세 OA-21276](https://data.seoul.go.kr/dataList/OA-21276/A/1/datasetView.do): 월세 0인 순수 전세. 전체 공개행이 같으면 중복 제거하며 계약해제 필드가 없어 개별 해제 여부는 확인하지 못합니다.
- [서울시 건축물대장 총괄표제부 OA-23051](https://data.seoul.go.kr/dataList/OA-23051/S/1/datasetView.do): 용적률. 주소·세대수·준공연도와 산정 면적이 맞는 공시값만 사용하며 동별 비율을 평균내지 않습니다.

전체 구 내려받기는 원천에서 세대수 필터를 지원하지 않아 검증 중 메모리에서 사용합니다. 배포하는 거래 상세는 위 대상 단지와 연결된 자료만 저장합니다. 300세대 미만 단지 거래를 배포 데이터에 포함하지 않습니다.

59㎡에 정확한 거래가 없으면 기존 UI의 45~75㎡ 미만 대체 타입 규칙을 유지합니다. 팝업에서 실제 선정 면적·월·층을 확인하세요. 최고층 정보가 없으면 관측 최고층을 제외합니다. 가격 대표성과 신뢰도는 기존 비교 규칙의 참고 등급이며 통계적 확률이 아닙니다.

서울 전역·경기도 데이터는 이번 버전에 포함하지 않았습니다. 추가 지역은 설정만 늘리기 전에 공식 단지 목록·거래 연결 근거·범위 검증을 준비해야 합니다. 경기도는 별도 공식 원천 수집기가 필요합니다.
