# k.APT_v32 · 서울 전역·경기 주요 지역

v26 화면 배치·급지표·지도 업로드·저장/되돌리기/복구·가격 계산을 유지하고, 서울 25개 구와 경기 성남·과천·안양·화성·광명 데이터를 적용했습니다. 분당은 성남, 평촌은 안양, 동탄은 화성에 포함됩니다. 경기도 전체를 수집한 버전은 아닙니다.


## v32 전체 설치와 이름 변경

프로그램 이름과 좌상단 표시를 k.APT_v32로 변경했습니다. v28 이후의 데이터·역 연결·메모 아이콘·이미지 보관·계정 동기화에 필요한 파일을 모두 포함합니다. v29/v30/v31을 먼저 적용하지 않아도 전체 파일을 덮어쓰면 사용할 수 있습니다. 기존 저장 키는 유지합니다.

## v31 계정 동기화

상단 로그인 버튼에서 Supabase 이메일 가입/로그인과 비밀번호 재설정을 지원합니다. 같은 계정으로 로그인하면 현재/저장 필터, 메모, 즐겨찾기, 지역/기타 이미지와 제목을 동기화합니다. 첫 사용 시 [설정 안내](docs/SUPABASE_SETUP.md)에 따라 전용 프로젝트 또는 기존 프로젝트에 `supabase/setup.sql`을 실행하고 `config/supabase.js`의 URL과 공개 키를 넣으세요. 실제 접속 정보는 배포본에 들어 있지 않습니다.

기존 브라우저 자료는 따로 보관하며 서버에 자료가 없는 첫 계정 로그인 때 가져옵니다. 계정 전환 시 다른 계정의 자료가 섞이지 않습니다. 네트워크 실패 시 로컬 변경을 남기고 다시 시도하며, 동시 수정은 서버 버전 확인과 항목별 병합으로 처리합니다. 자세한 합치기 규칙과 제한은 설정 안내를 참조하세요. 아파트 원본 데이터와 월별 업데이트 설정은 v30과 같습니다.

공식 Supabase JS 2.102.0 SDK를 assets/vendor에 함께 넣어 별도 CDN 로딩 없이 실행합니다. 이미지에는 비공개 버킷을 사용하고 테이블/파일의 접근 정책은 로그인 사용자 ID를 확인합니다. Secret/service_role 키는 프런트엔드에 사용할 수 없도록 입력을 차단합니다.

## v30 이미지 보관 탭

- 참고 창에 지역 / 지하철역 / 기타 탭을 제공합니다.
- 기타의 ＋ 버튼에서 캡처 이미지 파일을 여러 장 추가할 수 있습니다. 한 장만 추가하면 제목 편집 창이 바로 열립니다. 여러 장은 파일명을 기본 제목으로 쓰고 각각 편집할 수 있습니다.
- 큰 미리보기는 왼쪽, 썸네일은 오른쪽에 위에서 아래로 나열합니다. 많아지면 다음 열로 이어지고 목록 안에서 스크롤합니다. 좁은 화면에서는 미리보기 아래에 목록이 놓입니다.
- 지역과 기타 썸네일 아래쪽 이미지 위에 편집/삭제 버튼을 겹쳐 놓고 제목은 썸네일 아래에 표시합니다. 편집에서 제목만 수정하거나 이미지 파일도 교체할 수 있습니다.
- 미리보기 클릭 시 기존 확대·이동 창을 엽니다. PNG/JPG/WEBP/GIF, 파일당 30MB까지 지원합니다.
- 기존 지역 이미지 저장소(kAptReferenceMapsV1)를 유지합니다. 이전 버전 이미지·제목·선택 항목을 보존하며 기타 이미지는 구분해서 저장합니다. 메모·필터·즐겨찾기의 기존 저장 키도 유지합니다.
- 같은 사이트 주소의 같은 브라우저에서 업데이트하면 저장 내용을 계속 사용합니다. 다른 브라우저·기기나 다른 사이트 주소에는 자동 동기화되지 않습니다. 브라우저 데이터 삭제·시크릿 모드·저장 공간 정리로 사라질 수 있습니다. 파일을 직접 여는 file:// 저장 동작은 브라우저마다 다르므로 지속 사용에는 같은 웹 주소를 권장합니다.
- Supabase나 로그인은 이 버전에 추가하지 않았습니다. 월별 데이터 갱신 설정과 아파트 데이터는 v29와 같습니다.

## v28 표시·지도 링크 변경

아파트 이름 아래에 공식 데이터의 구/시·구·법정동을 작게 표시합니다. 예: 당산푸르지오(2,9당산역) 아래 영등포구 영등포동8가. 동정보가 없는 경우 임의의 동을 채우지 않습니다.

- 일반 클릭: 기존 N페이 부동산 링크.
- Ctrl+클릭: 지역명+단지명으로 네이버 지도 검색을 새 탭에서 엽니다.
- 맥 Command(⌘)+클릭도 동일하게 지원합니다. macOS의 Ctrl+클릭 메뉴 동작도 처리합니다.
- 지도 검색 결과가 여러 개면 원하는 아파트를 선택하세요. 지도 장소 ID를 추정해서 넣지 않았습니다.
- 위치 글씨의 형광펜은 1급지 연한 빨강, 2급지 연한 주황, 3급지 노랑, 4급지 연한 초록, 5급지 연한 파랑, 6급지 연한 회색이며 배경색만 불투명도 50%입니다.

색은 화면의 현재 6단계 급지표를 따릅니다. 여의도동·성수동·목동·흑석동·마곡동·북아현동·청량리동·수색동·신도림동·중계동·길음동 등 명확한 법정동 예외를 반영합니다. 경기는 과천 1, 분당 2, 위례 창곡동/철산동 3, 광명 나머지 4, 동안구/동탄구/성남 중원구 5로 표시합니다. '동탄역 생활권', '평촌 핵심지', '수정구 핵심지'처럼 검증된 생활권 경계가 없는 예외는 임의로 단지 범위를 넓히지 않고 기본 구 범위를 사용합니다. 급지표에 없는 범위는 회색으로 표시하고 툴팁에 급지 미분류를 안내합니다. 즐겨찾기 칩의 사용자 지정 색은 별도로 유지합니다.

매매·전세·용적률·가격 계산·갭 기준은 v27과 동일하며, 특정 매매 세대의 전세 연결 기능은 추가하지 않았습니다. v27에 포함된 데이터와 월별 갱신 설정을 그대로 유지합니다.

## 바로 사용하기

ZIP을 **모두 풀고 폴더 안의 index.html을 여세요.** index.html과 data/regions 파일들을 같은 프로젝트에 두어야 합니다. 지역별 데이터가 누락되면 부분 자료로 잘못 비교하지 않도록 안내하고 표를 비웁니다.

데이터를 지역별 파일로 나눠 GitHub 웹에서도 올릴 수 있게 했습니다. 각 파일은 8MiB 이하입니다. data/site-data.json은 지역 파일 목록·해시이며, 이전 자료는 data/site-data.previous.json의 목록이 가리키는 파일로 보관합니다. Python에서는 pipeline.read_json으로 기존 통합 구조를 복원합니다.

## 비교와 필터

지역·세대수·면적·준공일자·시작 기준가·신뢰도·전세 갭을 같은 계산 규칙으로 적용합니다. 지역 즐겨찾기에 30개 구/시가 들어 있으며 `전체`는 불러온 범위를 선택합니다. 분당구·동안구·동탄구 등 실제 구 필터도 추가할 수 있습니다. `평촌동`은 법정동 범위로, 평촌 생활권 전체와는 다릅니다. 원래 UI의 `동탄시` 선택은 화성 동탄구 자료를 가리키는 호환 선택입니다.

전세 기준은 선택한 시작월과 이전 5개월, 같은 실제 면적 ±0.1㎡, 4층 이상·최고층 제외 조건에 맞는 순수 전세의 최고가입니다. 선택한 시작월 매매 기준가에서 이를 빼서 갭을 계산합니다. 끝월을 바꿔도 시작점의 갭은 바뀌지 않습니다. 전세 계약이 없거나 조건에 맞지 않으면 값을 채우지 않습니다. 전세도 2024.01부터 포함하므로 2024.01~05를 시작점으로 고르면 직전 6개월 전체 자료가 포함되지 않습니다. 시작 매매 기준월이 시작월보다 3개월을 초과해 뒤로 밀리면 갭을 계산하지 않습니다. 가격·전세·용적률 숫자를 눌러 선정 근거를 확인하세요.

- **서울**: 원천의 신규/갱신 구분을 반영하며 기본은 신규 계약입니다. 확인된 총괄 대장 용적률만 필터에 사용합니다.
- **경기도**: 공개 원천이 전세 신규/갱신 구분을 제공하지 않습니다. **전세 조건을 전체 계약으로 선택해야 전세 기준가와 갭이 계산됩니다.** 신규 선택에서는 이유를 안내합니다. 미상을 신규로 처리하지 않습니다.
- **경기도 용적률은 아직 확보하지 못했습니다.** 확인 필요로 표시하고, 용적률 수치 범위를 지정하면 경기도 미확인 단지를 제외합니다. 서울의 미확인 용적률도 같습니다.
- **새 지역 지하철 도보 경로는 검증하지 않았습니다.** 기존 영등포 도보 연결 외에 직선거리로 임의 도보 시간을 채우지 않았으므로 새 지역 비교는 지역/APT 선택을 사용하세요.

59㎡의 정확한 거래가 없을 때 기존 45~75㎡ 미만 대체 타입 규칙을 유지합니다. 팝업에서 실제 면적·선정월·층을 확인하세요. 최고층 기본정보가 없으면 관측 최고층을 제외합니다. 신뢰도는 기존 가격 대표성 참고 등급이며 통계적 확률이 아닙니다.

## 기존 GitHub 저장소에 적용

1. 기존 저장소를 백업하고, ZIP 폴더의 내용 전체를 같은 경로에 덮어씁니다. **index.html만 교체하지 마세요.** data 폴더와 scripts, config, reports, tests를 함께 올립니다.
2. **.github/workflows/update-data.yml**도 교체하세요. .github는 압축 프로그램에서 숨김 폴더로 표시될 수 있습니다. workflow와 수집기를 함께 바꾸지 않으면 다음 실행에 새 범위가 반영되지 않습니다.
3. 같은 저장소·사이트 주소를 유지하면 필터 세이브 10개·고정 상태·지도 업로드 저장 키를 이어 사용합니다. 다른 도메인·브라우저·로컬 파일 주소에는 저장 내용이 자동 이동하지 않습니다.
4. 포함 자료를 보는 데에는 **Actions → Run workflow가 필요 없습니다.** 최신 자료를 다시 받거나 원격 수집 동작을 확인할 때 수동 실행하세요.

## 월별 자동 갱신

GitHub Actions 설정은 **매월 1일 한국시간 04:00**을 목표로 서울 25구와 경기 5시를 수집합니다. UTC 19:00, 한국 달력 1일 검사로 월 길이 차이를 처리합니다. GitHub 예약 실행은 지연될 수 있습니다.

기존 저장소의 Actions가 활성화되어 있고 쓰기 권한을 허용해야 합니다. 수집 커밋이 기존 배포에 연결되어야 사이트에 반영됩니다. ZIP 다운로드나 로컬 HTML 실행만으로 자동 갱신이 실행되지는 않습니다. 이번 작업에서 원격 업로드·Actions 실행·배포를 수행한 것은 아닙니다.

API 인증키 없이 공식 공개 내려받기와 공개 조회 화면을 사용합니다. 서울 매매·전세를 구별로, K-apt 기본정보를 한 번, 경기 거래를 공식 법정동·연도별로 수집합니다. 화성은 현재 4개 구 코드뿐 아니라 이전 행정구역 자료를 함께 받아 과거 거래를 연결합니다. 공개 화면에 표시된 법정 리를 확인해 읍·면 응답이 다른 리에 섞이지 않도록 합니다. 오산동에서 여울동으로 바뀐 공식 명칭도 반영합니다. 같은 날짜·면적·층·가격 등 공개 필드가 모두 동일한 경기 자료행은 중복 제거합니다. 이는 계약 고유 ID에 따른 정확한 계약 건수 집계가 아닙니다.

새 실행에서는 제공 기간 전체를 다시 받아 취소·지연 신고를 반영합니다. 원천 해시·확인 시각·조회 범위는 보고서에 기록합니다. 시군구/법정동 응답 필터, 대상 목록 급감, 지역별 월 전체 누락, 기존 단지 자료 급감, 계약일·수치 범위, 지역 파일 개수와 해시를 검사합니다. 서울 또는 경기 수집·범위 검증이 실패하면 새 전체 자료를 발행하지 않고 이전 정상 데이터/화면을 유지합니다. 오류 보고서는 workflow artifact에서 확인할 수 있습니다.

Python 3.11 이상, 수집기는 표준 라이브러리만 사용합니다. 최초 수집은 범위가 넓어 오래 걸릴 수 있습니다. 원천 화면 형식 변경이나 일시 장애는 수정·재실행이 필요할 수 있습니다.

```bash
python -m unittest discover -s tests -v
python scripts/update_public.py
python scripts/validate.py
```

## v29 변경

- 역·노선: 전체 2,157단지에 대해 K-apt 공개 지도 좌표와 OpenStreetMap 보행 가능 도로·역 출입구를 연결했습니다. 1.3km/65m·분⁻¹ 기준 20분 이내만 사용합니다. 1,540단지 3,525개 단지–역 연결, 보행망상 기준 안의 역 없음 586단지, 좌표 미확인 24단지, 보행망 연결 미확인 7단지입니다. 단지명에는 가장 가까운 역·노선을 붙입니다. 다른 연결 역은 단지명 마우스오버 안내와 역 필터에 포함됩니다. 기존 1~50위 외에도 이번에 연결한 역을 추가 검색할 수 있으며 순위 없는 역은 뒤에 배치됩니다.
- 도보는 **보행망 추정**입니다. 단지 출입문을 개별 확인한 측정값이 아닙니다. 단지 지도 좌표에서 출발하며 보행망에 150m 안으로 연결되는 경우만 계산합니다. 역의 출입구가 미등록이면 역 좌표를 사용하며 해당 항목에 표시합니다. 출입문·공사·통행 제한·지도 누락에 따라 실제 지도 길찾기와 다를 수 있습니다. 알려진 가까운 역이 있어도 좌표·보행 연결이 미확인인 단지에는 추측한 값을 넣지 않습니다.
- 광장현대5단지: 강변역(2) 844m, 광나루역(5) 913m. 동탄역 롯데캐슬: 동탄역(GTX-A) 302m. 당산푸르지오: 당산역(2·9) 481m. 모두 위 기준의 추정이며 실제 출입문에서의 도보 시간을 확정한 수치가 아닙니다. SRT 등 일반 고속철도까지 별도로 전수 연결한 것은 아닙니다.
- 전세: 시작월과 **이전 12개월까지** 포함합니다. 2025.09 시작이면 2024.09~2025.09를 포함하여 정확히 1년 전 같은 달도 산입합니다. 같은 면적·저층 1~3층·최고층 제외·계약 구분 선택·최고가 선정은 유지했습니다. 갭은 시작 매매 기준가 기준입니다.

### 설치·갱신

압축을 푼 **전체 프로젝트**를 기존 저장소에 반영하세요. data/regions와 assets의 SVG까지 포함해야 합니다. 화면 변경을 보기 위해 Actions를 수동 실행할 필요는 없습니다. 매월 1일 04시 갱신 workflow는 기존 매매·전세 수집 후 공개 보행망의 역 연결도 갱신합니다. 역 수집 실패 시 기존 연결을 유지하고 reports/transport-report.json에 기록합니다.

역 연결만 수동 갱신하려면 `python -m pip install -r requirements-transport.txt` 후 `python scripts/update_transport.py`를 실행합니다. 공식 좌표와 한국 OSM PBF(약 275MiB)를 내려받으므로 수 분과 메모리가 필요합니다. 원천 크기와 서버 응답에 따라 시간이 달라집니다. 소스 형식 변경 시 마지막 정상 자료를 보존합니다. 자동 갱신·원격 배포 자체는 이 작업에서 실행하지 않았습니다.
