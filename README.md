# k APT Dashboard v20 — 4개구 검증판

v18에서 정상 작동하는 **UI·필터·즐겨찾기·저장/불러오기·가격 계산 JavaScript를 그대로 유지**하고, 데이터 수집/병합 파이프라인만 영등포구·마포구·성동구·동작구 4개구로 확장한 버전입니다.

- 마포구 실거래에 존재하는 괄호형 단지명 `"(91-511)"`이 기존 정규화에서 빈 문자열이 되던 문제를 수정했습니다.
- 괄호 제거 뒤 이름이 비면 원래 문자열을 이용해 `91511`처럼 식별하도록 변경했습니다.
- 동일 지역·동일 정규화명·동일 주소가 다시 생겨도 거래를 합쳐 한 단지로 만드는 최종 중복 방어 로직을 추가했습니다.
- 위 사례를 self-test에 회귀 테스트로 추가했습니다.

서울 전체나 경기 지역은 이번 v20에서 수집하지 않습니다. 4개구가 안정적으로 끝까지 성공하는 구조를 먼저 검증한 뒤 다음 버전에서 소규모 묶음으로 확대하는 전제입니다.

## 초기 ZIP 안의 데이터

ZIP을 열자마자 화면이 깨지지 않도록 다음 데이터를 seed로 넣었습니다.

- 영등포구: 첨부된 정상 v18 데이터 그대로 유지
- 마포구·성동구: 이전 정상 3개구 수집본에서 복구
- 동작구: GitHub Actions의 첫 `full` 실행에서 공식 실거래 + 서울 공개 메타데이터를 수집하여 추가

따라서 **GitHub Actions 첫 성공 실행 후 `loaded_regions`가 정확히 4개구가 되고 v20 완성 상태(`full_v20_4gu`)가 됩니다.** 첫 실행 전에는 안전한 bootstrap 상태이며 기존 화면 기능을 망가뜨리지 않습니다.

## 한 번의 Run workflow가 하는 일

1. 4개구를 각각 별도 job으로 수집합니다. (`max-parallel: 2`)
2. 각 구마다 요청한 모든 월이 성공했는지, 단지/거래가 실제로 들어왔는지 검증합니다.
3. 한 구라도 실패하면 merge/publish job은 실행되지 않습니다.
4. 네 구가 모두 성공한 경우에만 `data/site-data.json`으로 병합합니다.
5. 같은 JSON을 `index.html`의 `window.__EMBEDDED_DATA__`에 내장합니다.
6. v18 핵심 UI 함수/필터 규칙이 남아 있는지 다시 정적 검증합니다.
7. 검증을 통과한 `site-data.json`과 `index.html`만 자동 Commit/Push 합니다.
8. Vercel이 연결돼 있다면 Push 후 자동 재배포됩니다. 브라우저를 켜둘 필요가 없습니다.

## 보존한 핵심 가격 규칙

가격 계산은 v18 브라우저 로직을 그대로 사용합니다.

- 시작 기준월 거래가 없으면 이후 첫 거래월 탐색
- 최근 기준월 거래가 없으면 이전 거래월 탐색
- 한 건뿐인 월도 대표가 사용 가능
- 동일 거래가 시작/최근에 동시에 잡히면 상승액·상승률 0
- 1~3층 제외
- 최고층 제외
- 59㎡ 우선, 없으면 45~74.99㎡ 중 59㎡에 가장 가까운 타입 사용
- 84㎡는 기존 허용 범위 유지
- 시작/최근 시점 및 층 차이 기반 신뢰도 로직 유지
- 세대수·용적률·준공·시작가격·신뢰도 등 기존 필터 로직 유지
- 즐겨찾기 지역/지하철역/APT, 색상·순서, 상단 전체/저장/불러오기 유지
