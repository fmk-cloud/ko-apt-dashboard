# k APT Dashboard v21 — 4개구 안정화판

v18에서 정상 작동한 **UI·필터·즐겨찾기·저장/불러오기·가격 계산 JavaScript는 그대로 유지**하고, v20에서 확인된 마포구 과거월 API 타임아웃을 피하도록 데이터 수집 구조를 바꾼 버전입니다.

## v21에서 바뀐 핵심

- v20 실패 원인: 마포구 `2022-09` 국토부 실거래 API가 60초 × 5회 모두 timeout.
- 이미 `data/site-data.json`에 존재하는 지역은 과거 전체를 다시 받지 않습니다. **최근 6개월만 재수집**합니다.
- 기준 데이터에 없는 지역만 `start_month`부터 전체 수집합니다. 현재 초기 ZIP에서는 동작구가 여기에 해당합니다.
- 따라서 첫 v21 실행은 영등포·마포·성동 = 최근 6개월 갱신, 동작 = 2022-09부터 전체 수집입니다.
- 첫 성공 후에는 동작구도 기준 데이터에 포함되므로 이후 4개구 모두 최근 6개월만 갱신됩니다.
- 최근 6개월 갱신은 **모든 월을 먼저 성공적으로 다운로드한 뒤** 기존 최근 거래를 교체하는 원자적 방식입니다. 중간 월에서 timeout이 나면 그 지역 결과를 만들지 않아 부분 갱신 데이터가 배포되지 않습니다.
- v20의 `"(91-511)"` 단지명 정규화/중복 방어 수정도 그대로 유지합니다.

## 대상 지역

- 영등포구 `11560`
- 마포구 `11440`
- 성동구 `11200`
- 동작구 `11590`

## Run workflow

Actions → **Update 4 districts apartment data v21** → **Run workflow**를 누릅니다.

`start_month`는 기본값 `2022-09` 그대로 두면 됩니다. 이 값은 이제 **기준 데이터에 아직 없는 신규 지역의 최초 전체 수집 시작월**입니다. 기존 지역을 매번 2022-09부터 다시 수집한다는 뜻이 아닙니다.

실행 구조:

1. self-test 및 정적 검증
2. 4개구 독립 job
3. 기존 지역은 최근 6개월만 갱신, 없는 지역은 전체 수집
4. 각 지역의 요청 월이 모두 성공했는지 검증
5. 4개구 모두 성공한 경우에만 병합
6. `site-data.json` 생성 → `index.html` 내장 → 최종 검증 → Commit/Push

한 지역이라도 실패하면 `merge_publish`는 실행되지 않습니다.

## 보존한 v18 가격/UI 규칙

- 시작 기준월 거래가 없으면 이후 첫 거래월 탐색
- 최근 기준월 거래가 없으면 이전 거래월 탐색
- 한 건뿐인 월도 대표가 사용 가능
- 동일 거래가 양쪽에 잡히면 상승액·상승률 0
- 1~3층 제외
- 최고층 제외
- 59㎡ 우선, 없으면 같은 20평대에서 59㎡에 가장 가까운 면적 사용
- 세대수·용적률·준공·가격·신뢰도 필터 유지
- 즐겨찾기 지역/지하철역/APT, 색상·순서, 저장/불러오기 유지
