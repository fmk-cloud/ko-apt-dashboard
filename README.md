# k APT Dashboard v19 · 영등포구

기존 v18 화면을 유지하면서 영등포구 300세대 이상 아파트의 매매 실거래를 공식 공개자료로 다시 연결한 버전입니다. ZIP을 풀고 `index.html`을 브라우저로 열면 포함된 데이터로 즉시 사용할 수 있습니다. Python 설치나 인증키는 화면을 열 때 필요하지 않습니다.

## 이번 버전

- 데이터 기간·세대수·시작 기준가·전용면적·준공일자·신뢰도 필터, 즐겨찾기, 필터 저장/복구.
- 좌상단 `불러오기`만 `복구`로 변경했습니다. 팝업의 `불러오기`는 유지했습니다.
- 용적률과 매매–전세 갭은 미지원입니다. 기존 버튼·선택지·팝업을 보존하고 불투명한 연한 붉은색으로 표시했습니다. 값을 선택해도 검색 결과에는 반영하지 않습니다. 기존 용적률 숫자는 미검증 샘플 표시이며 새로 수집한 값이 아닙니다.
- 매월 1일 한국시간 04:00 갱신 목표의 GitHub Actions가 포함되어 있습니다. **이 파일을 내려받는 것만으로 서버의 자동 실행이 켜지지는 않습니다.** 아래 설치가 필요합니다.

## 가장 먼저 실행하기

1. ZIP을 풀고 `index.html`을 Chrome 또는 Safari로 엽니다.
2. 59㎡와 84㎡를 선택하고 시작·최근 기준월을 정합니다. `전체`는 필터 범위를 넓히는 버튼입니다.
3. 각 행의 신뢰도를 클릭하면 실제 선정 거래·면적·층·선정월과 제외 사유를 확인할 수 있습니다.
4. 화면 위 `수집 현황`을 펼치면 현재 필터와 무관한 전체 대상 목록, 단지별 거래 건수, 수집 보류 사유를 볼 수 있습니다.
5. `저장`/`복구`는 같은 브라우저의 필터 설정을 저장/복구합니다. 거래 데이터 백업이나 다른 기기 동기화 버튼이 아닙니다. 즐겨찾기도 브라우저 저장소를 사용합니다.

## 자동 업데이트 설치 — GitHub + 기존 Vercel

1. 기존 사이트와 연결된 GitHub 저장소의 **기본 브랜치**에 이 폴더의 내용을 덮어씁니다. `index.html`이 저장소 최상위에 있어야 합니다. `config`, `data`, `scripts`, `tests`, `reports`, `.github` 폴더도 모두 올립니다.
2. macOS에서 `.github`가 보이지 않으면 Finder에서 `Command + Shift + .`로 표시합니다. 이전 `update-data.yml`을 새 파일로 교체해야 합니다.
3. GitHub 저장소의 `Actions`에서 **Update Yeongdeungpo data**를 엽니다. 비활성 안내가 나오면 활성화합니다. `Run workflow`로 한 번 수동 실행합니다.
4. 작업이 초록색으로 완료되고 `Update Yeongdeungpo official apartment data` 커밋이 생겼는지 확인합니다. 브랜치 보호 규칙이 봇의 직접 쓰기를 막으면 이 작업도 실패합니다. 강제 푸시하거나 보호 규칙을 자동 해제하지 않습니다.
5. Vercel의 Git 연동이 해당 기본 브랜치 커밋을 배포하도록 설정되어 있는지 확인합니다. Vercel에서 새 배포 성공 여부와 화면 상단 데이터 날짜를 확인합니다. GitHub 갱신 성공과 Vercel 배포 성공은 별개입니다. 봇 커밋에 대한 배포가 차단되는 계정/프로젝트라면 Vercel 설정을 확인하고 해당 커밋을 재배포해야 합니다.

API 인증키와 Python 패키지 설치는 필요 없습니다. Vercel에서는 정적 사이트로 배포합니다. 화면 실행에 서버 DB는 필요 없습니다.

스케줄은 GitHub Actions가 제공하는 UTC 기준입니다. 매월 말 28~31일 19:00 UTC에 실행 후보를 만들고, 한국시간 1일인 실행만 수집합니다. 2월·윤년·연도 변경을 처리합니다. GitHub의 실행 대기 때문에 정확히 04:00에 끝나는 것을 보장하지는 않습니다. 비활성 저장소의 예약 실행 중단, 서비스 장애, 권한 제한도 있을 수 있으므로 Actions 실패 알림을 켜두세요. 실행 대상은 기본 브랜치입니다.

## 데이터 범위와 정확성

매매 원천: [서울시 부동산 실거래가 정보 OA-21275](https://data.seoul.go.kr/dataList/OA-21275/S/1/datasetView.do) (국토교통부 연계).
단지 원천: [서울시 공동주택 아파트 정보 OA-15818](https://data.seoul.go.kr/dataList/OA-15818/S/1/datasetView.do).
출처를 표시하고 사용하는 공공누리 제1유형 공개자료입니다. 구현은 공개 페이지의 JSON 내려받기 기능을 사용합니다. 공개 내려받기 주소/응답 형식이 변경되면 수집 코드를 고쳐야 합니다.

- 현재 포함 기간은 **2024.01~2026.09**, 종료월은 실행 시점의 직전 완료월입니다. 월초에는 직전월 미신고 거래가 있을 수 있습니다. 매달 제공 범위 전체를 다시 받아 지연 신고·해제 신고를 반영합니다.
- 공식 목록에서 영등포구, 300세대 이상 아파트/주상복합을 선별하고 임대 전용을 제외합니다. 전체 구 원자료를 메모리에서 검증한 뒤 대상에 연결된 거래 상세만 저장합니다. 다운로드 자체는 구 전체를 받는 방식이며 원천 서비스에서 세대수 조건을 지정할 수는 없습니다.
- 법정동·지번·거래명·건축연도를 함께 확인해 연결합니다. 비슷한 이름만으로 연결하지 않습니다. 연결표는 `config/seoul-bindings.json`입니다.
- **당산상아**는 공식 관리 목록에 있으나 거래 연결을 확인하지 못했습니다. 가격을 추정해 채우거나 다른 재건축 단지에 합치지 않고 확인 필요로 표시합니다.
- **신대림자이**는 관리 목록에서는 314세대이지만 거래단위 1·2차는 각각 155·159세대라 제외했습니다. [1차 근거](https://kbland.kr/se/c/15072), [2차 근거](https://kbland.kr/se/c/15073).
- **여의도광장**은 관리 단위 744세대와 서로 다른 지번의 거래 단위가 일치하지 않아 세대수 분리 확인 전 수집 보류입니다. 제외/보류 목록과 근거는 `config/catalog-exclusions.json`에 남겼습니다. 따라서 영등포구 모든 대상의 거래가 완벽히 연결되었다고 주장하는 버전은 아닙니다.
- 최근 공개자료는 접수연도 기준 제공 범위가 이동할 수 있습니다. 과거에 검증해 저장한 이전 연도 거래는 보존하되 원천 제공 기간 밖이면 취소 여부를 재확인할 수 없습니다. 이 경우 화면 수집 현황에 안내합니다. 2023년 소수 지연 신고를 완전한 2023년 데이터로 표시하지 않습니다.
- 해제 신고 거래·분양권·입주권은 제외합니다. 날짜·층·가격이 같은 별개 거래를 임의로 하나로 합치지 않습니다.
- 목록/응답 이상, 특정 월 전체 누락, 기존 단지 거래 급감은 발행을 중단합니다. 검증으로 모든 원천 누락을 발견할 수 있는 것은 아닙니다. 실패 시 원격 사이트는 기존 커밋의 정상 자료를 유지합니다.

## 가격 계산 — v18 규칙 유지

시작 기준가는 기준월부터 **이후 첫 유효 거래월의 최고가**, 최근 기준가는 기준월부터 **이전 첫 유효 거래월의 최고가**입니다. 서로 다른 월일 수 있으므로 표에 실제 선정월을 표시합니다. 4층 이상을 사용하고 최고층을 제외합니다. 실제 건물 최고층 정보가 없으면 수집된 거래의 관측 최고층을 사용하므로 실제 최고층과 다를 수 있습니다.

59㎡ 버튼은 기존 규칙대로 해당 면적 자료가 없으면 45~75㎡ 미만의 가까운 타입으로 대체할 수 있습니다. 84㎡도 같은 면적군의 대체 타입을 사용할 수 있습니다. 정확히 같은 면적·층의 반복매매 지수나 감정평가가 아닙니다. 기존 신뢰도는 통계적 확률이 아닌 선정월·층 차이 등의 규칙에 따른 참고 등급입니다. 가격 팝업에서 실제 조건을 확인하세요.

역명/역 분류와 기존 참고 이미지는 샘플에서 유지한 정보입니다. 새 도보 경로를 계산하거나 최신 철도망을 수집하는 기능은 이번 범위에 포함하지 않습니다.

## 개발·점검

Python 3.11 이상에서 외부 패키지 없이 실행합니다.

```bash
python -m unittest discover -s tests -v
python scripts/update_public.py
python scripts/validate.py
python -m http.server 8000
```

`http://localhost:8000`으로 접속합니다. `build_data.py`는 같은 수집기의 호환 진입점입니다. 별도 API 경로는 두지 않았습니다.

- `data/site-data.json`: 화면 원본 데이터
- `data/complexes.json`: 세대수 검증 대상 목록
- `data/site-data.previous.json`: 다음 갱신부터 생성되는 직전 정상 데이터
- `index.html`: 동일 자료가 내장되어 오프라인 실행 가능
- `reports/update-report.json`: 최근 수집 결과·해제/미연결/제외 요약·원본 SHA256
- `tests/test_pipeline.py`: 실패 보존·해제 반영·범위/이름 검증·스케줄 경계 테스트
- `docs/검증결과.md`: 전달 시점의 검증 결과

직접 로컬 수집을 실행할 때는 프로젝트 복사본에서 실행하세요. 원천 조회/검증 실패는 데이터와 HTML을 덮어쓰지 않습니다. 파일 쓰기 중 디스크 고장까지 완전한 트랜잭션을 제공하는 DB 구조는 아닙니다. 원격 공개는 전체 변경을 하나의 Git 커밋으로 반영합니다.
