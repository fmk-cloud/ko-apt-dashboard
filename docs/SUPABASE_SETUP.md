# k.apt 계정 동기화 설정

1. Supabase에서 Free 조직의 프로젝트를 하나 만듭니다. 기존 무료 활성 프로젝트가 하나라면 두 번째 프로젝트까지 무료로 만들 수 있습니다. 여러 조직 전체의 Owner/Admin 프로젝트 수를 합산하며 일시정지한 프로젝트는 제외합니다. 기존 프로젝트에 이 SQL을 실행하는 것도 가능하지만, 프로젝트 하나가 남아 있다면 k.apt 전용 프로젝트를 권장합니다.
2. SQL Editor에서 `supabase/setup.sql` 전체를 붙여 넣고 Run을 누릅니다. `kapt_workspaces` 테이블, 저장 함수, 비공개 `kapt-private-images` 버킷과 계정별 정책을 만듭니다. 기존 프로그램의 테이블이나 버킷을 삭제하지 않습니다.
3. Project Settings의 API/Data API에서 Project URL을, API Keys에서 **Publishable key** (`sb_publishable_…`) 또는 구형 **anon** 키를 복사합니다. **secret/service_role 키를 넣지 마세요.**
4. `config/supabase.js`의 빈 URL과 공개 키에 값을 넣습니다. 이 파일과 ZIP의 나머지 파일들을 현재 사이트에 올립니다. 이 설정은 모든 기기에 공통으로 배포됩니다. 파일 편집 대신 프로그램의 로그인 → Supabase 연결 설정에도 입력할 수 있지만 이 경우 다른 브라우저마다 같은 설정을 입력해야 합니다.
5. Authentication → URL Configuration의 Site URL에 현재 사이트 주소를, Redirect URLs에 실제 `index.html` 주소 또는 사용 중인 사이트 루트 주소를 등록합니다. 예: `https://사용자.github.io/kapt/`. 기존 프로젝트를 함께 쓰는 경우 기존 Site URL을 바꾸지 말고 k.apt 주소를 Redirect URLs에 추가하세요. 앱은 현재 주소로 이메일 인증/비밀번호 재설정 링크를 요청합니다. HTTPS 주소 사용을 권장하며 file://로 직접 열면 이메일 인증 복귀가 원활하지 않습니다.
6. Authentication → Providers에서 Email을 활성화합니다. 회원가입 후 인증 메일을 확인하고 로그인합니다. Supabase 기본 메일 서비스는 제한이 있으므로 인증 메일이 안 오면 스팸함과 Auth 설정을 확인합니다. 개인용으로 본인 계정을 Dashboard에서 직접 생성·인증하는 방법도 있습니다.
7. 첫 로그인 시 서버에 계정 자료가 없으면 이 브라우저의 기존 자료를 가져옵니다. 서버에 자료가 있으면 먼저 서버 자료를 불러옵니다. 추가로 합치고 싶으면 계정 창의 **기존 브라우저 자료 가져오기**를 누릅니다.
8. 다른 기기에서 같은 사이트와 같은 계정으로 로그인합니다. 계정 창에서 **동기화 완료**를 확인하세요. 자동 동기화는 변경 후 약 1초, 다른 기기 변경 확인은 약 30초 간격이며 **지금 동기화**로 바로 확인할 수 있습니다.

## 무엇을 저장하나요?

- 아파트 메모, 즐겨찾기(순서·색·선택 포함), 최대 10개 저장 필터와 고정 상태, 현재 필터 세팅.
- 지역/기타 이미지와 제목, 삭제 상태, 선택한 이미지.
- 이미지 파일은 비공개 버킷에, 나머지는 계정별 테이블 행에 저장합니다. 아파트 실거래 원본은 저장하지 않습니다.
- 같은 브라우저의 여러 탭은 같은 로그인 계정을 공유합니다. 다른 계정은 별도 브라우저 프로필을 사용하세요.
- 로그아웃하면 해당 계정의 캐시를 별도로 남기고 기존 비로그인 자료로 돌아갑니다. 다른 계정에 이전 계정 자료를 자동으로 업로드하지 않습니다.
- 네트워크 실패 시 로컬 변경을 보관하고 연결 복구 후 다시 동기화합니다. 완료 표시 전에는 브라우저 데이터를 지우지 마세요.
- 서로 다른 메모/이미지/저장 필터를 두 기기에서 동시에 수정한 경우 가능한 항목을 합칩니다. 같은 항목을 동시에 수정하면 마지막으로 성공한 기기의 수정이 적용됩니다. 즐겨찾기 순서 배열은 한 기기의 전체 순서가 적용될 수 있습니다. 겹치는 자료 가져오기는 브라우저 자료를 우선합니다.
- 계정·이미지 저장 키는 UI 버전 번호와 분리했습니다. 이후 버전에서도 같은 프로젝트와 사이트를 사용하세요.

## 비용과 연결 문제

- Free 활성 프로젝트는 총 2개까지입니다. 무료 저장 용량·트래픽 한도는 별도로 적용됩니다. 이미지가 많으면 사용량을 확인하세요.
- 이미지 삭제/교체는 동기화 목록에 즉시 반영됩니다. 다른 기기의 미전송 변경에 대비해 이전 파일을 자동으로 지우지 않으므로 저장 용량에 포함될 수 있습니다. 정리 전 활성 계정의 참조 경로와 미전송 변경을 확인해야 합니다.
- 무료 프로젝트는 장기간 비활동이면 일시정지될 수 있습니다. Supabase에서 Resume project로 재개한 뒤 지금 동기화를 누르세요. 브라우저 자료를 지우거나 새 프로젝트를 만들 필요가 없습니다.
- 이 배포본에는 실제 프로젝트 URL/키가 들어 있지 않습니다. 프로젝트 설정과 SQL 실행을 완료해야 실사용 동기화가 시작됩니다.
- RLS는 다른 계정의 행과 이미지 접근을 막습니다. 공개 키만 브라우저에 들어가고 비밀번호는 SDK를 통해 Supabase Auth에 전달하며 앱 자체가 저장하지 않습니다.
- 공유 컴퓨터에서는 사용 후 로그아웃하세요. 로컬 캐시는 계정 간 화면/업로드를 분리하지만 같은 OS 사용자로 컴퓨터를 사용하는 사람에 대한 암호화 저장소는 아닙니다.
